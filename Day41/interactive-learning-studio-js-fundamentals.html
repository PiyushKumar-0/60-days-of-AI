MODULE 01

Variables, Data Types & Operators

Foundational understanding: how JavaScript stores values, what kinds of values exist, and how operators combine them.

Explanation

JavaScript gives you three ways to declare a variable: var, let, and const. var is function-scoped and largely a legacy feature; let and const are block-scoped and are what modern code uses almost exclusively. Use const by default — it signals "this binding won't be reassigned" — and reach for let only when you know the value needs to change.

Every value in JavaScript has a type. The primitive types are string, number, boolean, undefined, null, bigint, and symbol. Everything else — arrays, functions, plain objects — is an object. JavaScript is dynamically typed: a variable's type is determined by the value it currently holds, and can change over its lifetime.

const name = "Ada"; // string let age = 30; // number const isDev = true; // boolean let nextRole; // undefined const manager = null; // intentionally empty console.log(typeof age); // "number"
Analogy: think of const and let as labeled boxes. const glues the label to one box forever — you can rearrange what's inside an object box, but you can't swap the box itself. let lets you peel the label off and stick it on a different box whenever you like.
Comparison

var

  • Function-scoped
  • Hoisted & initialized as undefined
  • Can be redeclared
  • Avoid in modern code

let / const

  • Block-scoped
  • Hoisted but not initialized (temporal dead zone)
  • Cannot be redeclared in the same scope
  • Preferred in modern code
Diagram — Type Coercion
Common misconception: "const makes a value immutable." It doesn't — it only prevents reassigning the variable. const arr = [1,2]; arr.push(3); is perfectly legal because the array's contents change, not the binding.

Key Takeaways

  • Prefer const; use let only when reassignment is needed; avoid var.
  • JavaScript has 7 primitive types plus the catch-all object type.
  • + coerces toward strings when either operand is a string; other arithmetic operators coerce toward numbers.
  • Use === (strict equality) instead of == to avoid surprising coercion during comparisons.

MODULE 02

Control Flow & Functions

From conditional logic to reusable blocks of behavior — the building blocks of every JS program.

Explanation

if/else statements branch based on truthy or falsy values. JavaScript treats 0, "", null, undefined, NaN, and false itself as falsy — everything else, including "0" and empty arrays/objects, is truthy.

Functions package logic for reuse. A function declaration is hoisted and can be called before its definition appears; a function expression or arrow function assigned to a variable is not. Arrow functions also don't bind their own this, which makes them ideal for callbacks but unsuitable as object methods that rely on this.

function greet(name = "friend") { return `Hello, ${name}!`; } const double = (n) => n * 2; if (double(5) > 8) { console.log(greet("Ada")); } else { console.log("too small"); }
Analogy: a function is a vending machine. You put in inputs (parameters/coins), it runs its internal process, and it returns an output (the snack). The machine doesn't care what's happening outside it — that's the whole point of encapsulation.
Comparison

Regular Function

  • Has its own this
  • Hoisted (declarations)
  • Can be a constructor
  • Has arguments object

Arrow Function

  • Inherits this from enclosing scope
  • Not hoisted the same way
  • Cannot be used with new
  • No own arguments object
Diagram — Truthy / Falsy
Common misconception: "An empty array or object is falsy." Both [] and {} are objects, and all objects are truthy — even empty ones. Only the specific falsy values shown above evaluate to false.

Key Takeaways

  • Falsy values are limited to: false, 0, "", null, undefined, NaN.
  • Function declarations are hoisted; function expressions and arrow functions are not.
  • Arrow functions don't have their own this — they inherit it from where they're defined.
  • Default parameters (name = "friend") avoid manual undefined checks.

MODULE 03

Arrays, Objects & Iteration

Practical application: structuring and transforming real data with the methods you'll use daily.

Explanation

Arrays are ordered lists; objects are collections of key-value pairs. Modern JavaScript favors declarative array methods — map, filter, reduce, forEach — over manual for loops, because they express intent: "transform each item" reads clearer than a loop with an index variable.

map returns a new array of the same length with each item transformed. filter returns a new array containing only items that pass a test. reduce folds the whole array down into a single value — a sum, an object, anything.

const prices = [10, 25, 40, 15]; const withTax = prices.map(p => p * 1.1); const expensive = prices.filter(p => p > 20); const total = prices.reduce((sum, p) => sum + p, 0); const user = { name: "Ada", role: "engineer" }; const { name, role } = user; // destructuring
Analogy: think of an assembly line. map is a station that reshapes every item passing through. filter is a quality inspector that only lets some items continue. reduce is the final packer who combines everything on the belt into one box.
Comparison

for loop

  • Full manual control
  • Can break/continue easily
  • More boilerplate
  • Imperative — describes "how"

map / filter / reduce

  • Concise, chainable
  • Returns new data (doesn't mutate)
  • No native early-exit
  • Declarative — describes "what"
Diagram — map vs filter
Common misconception: "forEach returns a new array like map." It doesn't — forEach always returns undefined; it's used purely for side effects, not transformation.

Key Takeaways

  • map transforms every item; filter selects some items; reduce combines into one value.
  • These methods return new arrays/values — they don't mutate the original (mutating methods like push do).
  • Destructuring (const {name} = obj) pulls values out of objects/arrays concisely.
  • forEach is for side effects only; it always returns undefined.

MODULE 04

Scope, Closures & Modern ES6+

Mastery: the mental model behind closures, and the modern syntax you'll see in every current codebase.

Explanation

Scope determines where a variable is visible. A closure is what happens when an inner function "remembers" the variables from its outer function's scope, even after the outer function has finished running. This is how private state and function factories work in JavaScript.

ES6 (2015) and later added syntax that's now standard: template literals for string interpolation, the spread/rest operators (...) for expanding or collecting values, and destructuring for unpacking. These aren't just shorthand — they change how idiomatic JS is written.

function makeCounter() { let count = 0; return () => ++count; // closure over `count` } const counter = makeCounter(); counter(); // 1 counter(); // 2 — count persists between calls const nums = [1, 2, 3]; const more = [...nums, 4, 5]; // spread const [first, ...rest] = more; // rest
Analogy: a closure is like a backpack. When an inner function is created, it packs up references to the variables it needs from its surroundings and carries that backpack with it wherever it goes — even if it leaves the place (scope) where it was created.
Comparison

Spread ...arr

  • Expands an iterable into individual elements
  • Used in array/function-call literals
  • Example: Math.max(...nums)

Rest ...args

  • Collects remaining elements into an array
  • Used in destructuring / function parameters
  • Example: function f(a, ...rest)
Diagram — Closure Scope Chain
Common misconception: "Closures copy the outer variable's value." They don't — they keep a live reference. If the outer variable changes after the closure is created, the closure sees the updated value, not a frozen snapshot.
Try It

Exercise — Reason about output

Key Takeaways

  • A closure lets an inner function retain access to its outer function's variables after that function returns.
  • Each call to an outer function creates a fresh, independent scope — closures don't share state across separate invocations.
  • Spread expands values; rest collects them — same ... syntax, opposite direction.
  • Template literals (`${x}`) replace manual string concatenation for readability.

Summary Notes

JavaScript's core model: values have types (primitives vs. objects); variables use block-scoped let/const; functions are reusable, closable-over blocks of logic; arrays and objects are transformed declaratively; and ES6+ syntax (destructuring, spread/rest, template literals, arrow functions) is the modern default. Closures are the trickiest but most powerful idea — master them and most "advanced" JS patterns become intuitive.
