STAGE 01 · PLANNING

Idea Validation & Market Research

Confirm there's a real problem worth solving before writing a line of code, and define who you're building for.

⏱ 3–5 days
🎯 Output: validated problem + ICP + positioning doc
Objectives
  • Identify a specific, painful problem for a narrow audience — not a vague market.
  • Confirm people are already trying (and failing) to solve this problem, ideally paying for partial solutions.
  • Define your ideal customer profile (ICP) and a one-sentence positioning statement.
Tasks
Best AI Tools
Claude / ChatGPT
Why: best for synthesizing research, drafting interview questions, and pressure-testing your idea with counterarguments.
Alternative: Perplexity for citation-backed market research
Perplexity
Why: real-time web search with sources — good for sizing competitors and finding existing discussion of the problem.
Alternative: Google + manual Reddit/forum search
Prompt Example
Act as a skeptical VC. Here's my SaaS idea: [describe idea and target user]. Poke holes in it: What's the strongest reason this fails? Who is already solving this, even partially? What would make you NOT invest? Be blunt.
Best Practices vs Common Mistakes

✓ Best Practices

  • Talk to real users before building anything
  • Look for people paying for a worse alternative
  • Narrow the ICP until it feels "too small"

✗ Common Mistakes

  • Validating only with friends/family who won't be honest
  • Picking a problem because it's technically interesting, not painful
  • Skipping validation because "I just know it'll work"
💡 Efficiency tip: batch your AI research into one long chat thread — reusing context across prompts saves re-explaining your idea every time and produces more consistent competitor comparisons.

STAGE 02 · PLANNING

Product Design & Architecture

Turn the validated problem into a scoped feature set, information architecture, and technical plan.

⏱ 4–6 days
🎯 Output: wireframes + tech stack + data model
Objectives
  • Cut scope to the smallest feature set that delivers the core value (true MVP, not v1.0).
  • Produce low-fidelity wireframes for the 3–5 core screens.
  • Choose a tech stack and sketch the core data model before coding.
Tasks
Best AI Tools
v0 by Vercel
Why: generates real, working React/Tailwind UI from a text description — fastest way from idea to clickable wireframe.
Alternative: Figma (manual) or Uizard for AI-assisted mockups
Claude (Extended Thinking)
Why: excellent for reasoning through data models, API design, and stack trade-offs with your specific constraints in mind.
Alternative: ChatGPT with a systems-design-focused prompt
Prompt Example
I'm building a solo SaaS MVP: [one-line description]. Core features: [list]. Propose a data model (tables/fields/relations) and a lean tech stack for a solo developer who wants to ship in under 8 weeks, optimizing for speed over infinite scale.
Best Practices vs Common Mistakes

✓ Best Practices

  • Design the data model before writing UI code
  • Pick a boring, well-documented stack you already know
  • Wireframe in grayscale first — resist styling too early

✗ Common Mistakes

  • Over-engineering for scale you don't have yet
  • Choosing a trendy stack purely to learn it
  • Designing every edge case before shipping a core flow
💡 Efficiency tip: feed your validated ICP and feature list directly into the wireframe prompt — specific, constrained prompts produce far more usable v0 output than generic ones.

STAGE 03 · EXECUTION

Full-Stack Build

Write the actual application — frontend, backend, database, and auth — using AI as a pair programmer.

⏱ 2–4 weeks
🎯 Output: working end-to-end application
Objectives
  • Build the core user flow end-to-end before polishing anything.
  • Wire up auth, database, and the primary "aha moment" feature first.
  • Keep every commit shippable — avoid long-lived broken branches.
Tasks
Best AI Tools
Claude Code
Why: handles multi-file changes, understands your whole repo, and can run/debug code directly from the terminal — ideal for a solo full-stack build.
Alternative: Cursor or GitHub Copilot for in-editor completion
Cursor
Why: tight in-editor AI chat and inline edits, good for fast iteration once the architecture is set.
Alternative: Windsurf, or plain VS Code + Copilot
Prompt Example
Here's my data model and the core user flow: [paste]. Implement the [feature name] end-to-end: API route, database query, and a minimal UI component. Follow the existing project conventions and keep it framework-idiomatic. Explain any assumptions you make.
Best Practices vs Common Mistakes

✓ Best Practices

  • Ship the thinnest possible vertical slice first
  • Review AI-generated code before merging — don't blind-trust it
  • Commit small, working increments daily

✗ Common Mistakes

  • Building every feature in parallel, none of them finished
  • Accepting AI code without understanding what it does
  • Polishing UI before the core flow actually works
💡 Efficiency tip: keep a short "project context" file (stack, conventions, schema) and paste it into new AI sessions — this cuts re-explanation time dramatically over a multi-week build.

STAGE 04 · EXECUTION

Testing & Quality Assurance

Catch the bugs and rough edges that would otherwise show up in front of your first real users.

⏱ 4–7 days
🎯 Output: tested, stable build ready for real users
Objectives
  • Verify the core flow works reliably across common edge cases.
  • Add automated tests for the highest-risk logic (billing, auth, data writes).
  • Fix obvious UX friction before anyone outside your team sees it.
Tasks
Best AI Tools
Claude Code
Why: can write test suites for existing code, run them, and iterate on failures autonomously — a big time saver for a solo dev.
Alternative: GitHub Copilot for individual test-case suggestions
Sentry / LogRocket (+ AI triage)
Why: catches real runtime errors post-deploy; pairing error logs with an AI assistant speeds up root-cause analysis.
Alternative: manual console logging + browser devtools
Prompt Example
Here's my [billing/auth] module: [paste code]. Write a test suite covering the happy path and the most likely failure modes (invalid input, network failure, race conditions). Flag any logic bugs you notice while writing the tests.
Best Practices vs Common Mistakes

✓ Best Practices

  • Prioritize tests on money-related and auth logic first
  • Test on a real mobile device, not just desktop devtools
  • Get 2–3 outside people to try it before public launch

✗ Common Mistakes

  • Aiming for 100% test coverage on a pre-revenue MVP
  • Only testing the happy path
  • Skipping QA because "it worked when I built it"
💡 Efficiency tip: ask AI to generate a test-case checklist from your feature list before writing any test code — it surfaces edge cases you'd likely miss on your own.

STAGE 05 · LAUNCH

Launch & Go-to-Market

Get the product in front of real users and convert the validation work from Stage 1 into signups.

⏱ 1–2 weeks
🎯 Output: live product + first cohort of users
Objectives
  • Deploy to production with monitoring in place.
  • Publish a landing page that speaks directly to the ICP's pain point.
  • Launch to the warmest channels first: your validation-interview list, relevant communities, and one launch platform.
Tasks
Best AI Tools
Claude / ChatGPT
Why: strong at drafting landing page copy, launch posts, and outreach emails in your voice, especially when given real user quotes.
Alternative: Copy.ai for high-volume variant generation
Midjourney / DALL·E
Why: quick way to produce a hero image, OG image, or launch graphic without hiring a designer for v1.
Alternative: stock imagery + Canva templates
Prompt Example
Write landing page copy for [product name], which helps [ICP] do [core outcome] without [pain point]. Include: headline, subheadline, 3 benefit bullets, and one CTA. Use plain, specific language — no generic SaaS buzzwords. Here are 3 real user quotes to draw from: [paste quotes].
Best Practices vs Common Mistakes

✓ Best Practices

  • Launch to warm audiences before cold ones
  • Personally message everyone from your validation interviews
  • Have monitoring/alerts live before the traffic spike

✗ Common Mistakes

  • Waiting for "perfect" before launching at all
  • Launching everywhere at once with no capacity to follow up
  • Generic landing copy that doesn't mention the specific pain point
💡 Efficiency tip: reuse the exact language your interviewees used to describe their pain (Stage 1 notes) in your landing copy — it converts far better than paraphrased marketing-speak.

STAGE 06 · GROWTH

Post-Launch Iteration & Growth

Turn first users into retained, paying customers — and start automating the repetitive parts of running the business.

⏱ Ongoing
🎯 Output: retention loop + automated growth motion
Objectives
  • Understand why users churn or don't activate, and fix the biggest leak first.
  • Build a lightweight feedback loop so priorities come from real usage, not guesses.
  • Automate recurring founder tasks (support replies, onboarding emails, reporting).
Tasks
Best AI Tools
Claude (with MCP/connectors)
Why: can be wired into support inboxes and analytics to draft replies and summarize usage trends automatically.
Alternative: Intercom Fin or Zendesk AI for support-specific automation
Zapier / Make (+ AI steps)
Why: stitches your tools together — new signup → welcome email → CRM update — without custom backend code.
Alternative: n8n (self-hosted, more control)
Prompt Example
Here's a week of user feedback and support tickets: [paste]. Group these into themes, rank them by frequency and severity, and recommend the single highest-leverage fix to ship this week.
Best Practices vs Common Mistakes

✓ Best Practices

  • Talk to churned users, not just happy ones
  • Automate only after a task has proven repetitive
  • Ship small improvements continuously, not big rewrites

✗ Common Mistakes

  • Adding features based on one loud user's request
  • Automating support before you understand common questions
  • Ignoring churn signals until revenue drops
💡 Efficiency tip: set a standing weekly prompt where you paste in the week's metrics and feedback and ask for a ranked action list — this turns iteration into a 10-minute ritual instead of an open-ended guess.

SUMMARY

Workflow Summary & Next Steps

Workflow Summary

This workflow takes a solo founder from an unvalidated idea to a launched, iterating SaaS product in roughly 6–10 weeks: validate the problem, design a scoped MVP, build it with AI pair-programming, test the critical paths, launch to warm channels first, then iterate based on real usage. The recurring theme is narrowing scope at every stage — the smallest validated problem, the smallest feature set, the smallest test surface, the warmest launch audience.
