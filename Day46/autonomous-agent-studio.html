🧩 Agent roster & responsibilities

The stop-check governs information flow between rounds: each round the Evaluator scores the current draft against the rubric, the Critic turns that score into concrete actionable feedback, and the Improver rewrites the draft using both. The Memory Manager distills what changed and why into a running memory log so later rounds don't repeat past mistakes. After each Evaluator call the orchestrator checks, in order: plateau (score gain < delta for 2 straight rounds), threshold (score ≥ target), then the hard cap — whichever fires first ends the loop and routes the latest draft to the Final Reviewer.

🏗️ Architecture overview

  • Orchestrator (this app): a JS state machine that sequences agent calls, threads history forward, and evaluates stop conditions after every round.
  • Agents: each is a single Claude API call with a dedicated system prompt and only the context it needs (draft, rubric, prior critique).
  • State: a history[] array of {round, draft, score, critique, delta} is the single source of truth the UI renders from.
  • Loop: a real while loop — no fixed round count. Every pass is a live API call to Evaluator, Critic, and Improver.
  • Resilience: each fetch is wrapped with retry/backoff (up to 2 retries) and the UI surfaces failures without crashing the run.

🚀 Extension ideas & further prompts

  • Add a Safety Monitor agent that screens each draft for policy risk before it reaches the Critic.
  • Persist history[] to a vector store so the Memory Manager can recall patterns across separate runs, not just this one.
  • Fan out the Executor into parallel drafts (N candidates) and let the Evaluator pick the best before the improvement loop starts.
  • Add a human-in-the-loop "approve / request another round" gate right before Final Reviewer fires.
  • Try prompting: "Add a Safety Monitor agent to this pipeline that runs after Executor and can halt the loop."
  • Try prompting: "Change the stop condition to require the Critic to explicitly approve, not just a numeric threshold."
