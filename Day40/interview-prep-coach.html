The system prompt design

The assistant is instructed to play a single, consistent role: a friendly, encouraging interview coach for entry-level candidates. The prompt fixes its scope (behavioral interview practice + STAR coaching only), its output contract (always return structured JSON with a spoken reply, a feedback object, and STAR-component flags so the UI can update deterministically instead of parsing free text), and explicit edge-case rules: what to do if the user goes off-topic, gives a one-word answer, asks to skip, or tries to get the model to do something unrelated (e.g. write code, discuss unrelated topics) — it redirects back to the interview politely rather than refusing bluntly, since the audience is a nervous first-time job seeker.

Why the UI choices fit this use case

A generic chatbot box would hide the thing new grads actually struggle with: knowing whether their answer had a Situation, Task, Action, and Result. So the STAR Tracker card lights up each letter live as the model detects it in the candidate's answer — turning an abstract framework into a visible checklist. The Feedback panel gives a persistent, scannable history of scored feedback (strong/mid/weak) alongside the chat, so the user isn't stuck re-reading old chat bubbles to see how they're improving over a session.

How the live API call works

Each turn sends the full conversation history plus the system prompt to https://api.anthropic.com/v1/messages. The prompt asks the model to reply with ONLY a JSON object (no prose, no markdown fences) containing:

{
  "reply": "coach's chat message to show the user",
  "feedback": {
     "score": "strong | mid | weak | null",
     "note": "1-2 sentence coaching note"
  } ,
  "star_detected": ["S","T"],
  "next_question": true
}

The JS parses this, appends reply as a chat bubble, updates the STAR tracker from star_detected, and (if present) renders a feedback card. Fenced code blocks are stripped defensively before parsing in case the model wraps the JSON.

Extending this

To go further, you could: (1) add a resume/job-description upload as extra context sent with every request for more tailored questions, (2) add memory across sessions by persisting the conversation and a running weak-spot profile, (3) add a "final report" step that summarizes strengths/gaps once N questions are done, or (4) wire in an MCP tool for a company-specific question bank instead of relying purely on the model's general knowledge.
